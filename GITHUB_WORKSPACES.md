# GitHub workspaces

Open the assistant, expand **GitHub repository**, enter an HTTPS GitHub URL or `owner/repository`, optionally choose a base branch, and click **Connect new workspace**. The app downloads an immutable snapshot of that branch and works on a separate copy on your stick. No system Git installation is required.

Public repositories can be read without a token. For private repositories and publishing, create a GitHub fine-grained personal access token selecting the repository with **Contents: Read and write** and **Pull requests: Read and write**. Editing GitHub Actions workflow files also requires Workflows write permission. Organization policies may require owner approval. Tokens stay in session memory, outside model context and saved workspace metadata. Re-enter the token when resuming after restarting the app. The update-download token is separate.

Ask Lite (or Lite + Max) to make changes. File writes still need approval. Choose **Review changes**, inspect before/after previews, enter a pull-request title and description, then **Create draft pull request**. Publishing uploads only reviewed changed files to a new `stick-ai/…` branch and creates a draft PR against the selected base. Subsequent reviewed edits update that same branch without force pushing. If someone changes the branch on GitHub, publishing stops; connect a fresh workspace to preserve their work. Closed or merged PRs require a fresh workspace. The app never merges the PR or writes your default branch.

Saved working files and baseline snapshots are under `logs/github/workspaces/<id>/` in the app folder, preserved by app updates. **Use local project** returns to `app/project`; saved repositories remain available through **Saved workspaces**. Reconnecting creates a new independent workspace. Chat history is reset when switching projects and is not saved. You can copy the displayed pull-request URL into your browser.

Models run on your computer. GitHub syncing and publishing require internet. Tasks stop when the app closes; this is not an always-on cloud coding service. The desktop currently edits files and does not execute repository programs or tests. Direct Max mode returns code only; use Lite or paired mode for file tools.

Current portable workspace limits are 64 MB compressed, 256 MB expanded, 20,000 files and 8 MB per file. Only regular files with portable names are supported. Symlinks, submodules, LFS archive substitution, export-ignore omissions and truncated Git trees are rejected rather than silently losing tracked files. Existing executable Git modes are preserved. `.gitignore` rules exclude untracked artifacts from publishing; tracked files remain included. Review previews show up to 12,000 characters per version and label binary or shortened previews; inspect complete local files when needed. Generated files remain local until you explicitly publish.
